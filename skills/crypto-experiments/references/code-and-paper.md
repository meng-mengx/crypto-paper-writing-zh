# 论文与实现对应核验

首次接触具体实现、切换论文或代码版本，或发现实验与原文有差异时，按本轮涉及部分核对。已有对应关系仍有效时直接复用，不要求每次重填全表。

## 确认对应对象

- 区分作者实现、第三方实现和本轮自编原型。记录代码的实际来源、提交 SHA；没有 Git 版本时保留发布版本或所用文件的哈希。论文记录所用版本及算法、定理、图表或实验设置的位置；代码更新时间与论文年份接近不能证明两者对应。
- 将本轮关键函数或调用链对应到原文的输入输出、参数、角色和阶段。按解释结果所需检查符号约定、挑战域、群与模数、序列化、状态、预处理及必要的输入验证；识别替代原语、删减步骤、硬编码假设和未实现组件。
- 缺少组件时先判断它是否影响本轮问题。可以单独核验的部分继续，说明范围；不能用局部原型的耗时冒充完整方案性能，也不把自编实现称为作者代码。对应关系和差异写入已有实验记录，与实际命令及原始结果相互定位。

## 最小复现示例

例如，本轮只核验原文某个验证算法中的关系：素数阶为 `q` 的群中，公钥为 `Y = g^x`，承诺为 `R = g^r`，响应定义为 `s = r + c*x mod q`，验证 `g^s = R*Y^c`。这是说明复现做法的代数例子，并非对某篇论文已完成的复现记录。

1. 从所用原文版本定位这条关系及挑战 `c` 的生成方式，确认代码中的群运算、标量约减、响应生成和验证函数分别对应哪一步。若代码采用减号约定，先判断它是否与相应验证式等价，而不是仅凭符号不同判错。
2. 运行能回答当前问题的最小样例：生成合法输入并核对等式，再选择有预期判定依据的篡改或边界输入。记录实际命令、参数、随机性控制、代码版本和原始输出；已有测试可复用，缺少测试时在已授权范围内补必要检查。
3. 将输出与原文预期逐项对照。若不一致，检查模数、群成员、符号、挑战编码和代码分支，保留失败输入，并检验最可能的原因。修改后用原失败输入及受影响的正常样例复查；未定位原因时保留未解决差异。
4. 报告实际完成的是局部关系核验、指定算法复现，还是完整实验复现。小群穷举或少量通过样例只能支持所检查的关系与实例；它们不证明大参数安全性、零知识性或完整协议安全。性能复现另需对齐安全等级、环境和计时口径。

理论工作不必为了这一流程添加代码或性能实验：能用推导、合法反例或相称的局部检查回答当前问题时，按该证据交付。

## 可运行代码交付

仅在本轮要求交付可运行代码时使用；文献阅读、实验设计和已有结果解释不触发。同版本且条件仍适用的核验直接复用，只补变化与缺口，保留仍有效的实验记录。

- **参考依据。** 复用或封装来源代码时，先直接运行所用固定版本，保存可追溯的输入和原生参考结果，再封装并对照；已有封装补取原版参考，已有有效参考可复用。无可用来源代码时，按实际实现身份核验，不虚构原码运行。
- **验收用例。** 从已核对的参考结果、标准向量或推导确定预期，不从待测程序输出反推合格值；沿用上文样例，按接口补变化输入、适用的错误输入和重复调用。随机算法按明确随机性、性质或恰当统计量比较，不一律要求字节相同。
- **交付环境。** 按交付说明，从实际交付文件在干净临时环境及不同路径完成必要安装与实际调用，检查依赖和输入是否齐全，不依赖开发环境的隐含包或写死路径。所需硬件、数据或外部能力不可用时，明确受影响的未验项，不扩大原授权或资源范围。
- **产物内容。** 按上文逐项对照返回值及文件中的关键数值、图表或其他内容；文件存在、接口列出或退出成功不能代替结果正确。保留实际覆盖与未验范围。
