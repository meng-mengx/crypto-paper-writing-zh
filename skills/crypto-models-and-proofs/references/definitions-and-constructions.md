# 定义与构造

用于建立安全模型、设计与修订构造、推进证明及检查协议性质。按当前缺口选用方法，不要求每篇都有随机预言机、分叉、两类敌手或状态更新。

## 从研究目标形成模型与构造

研究方向尚未收敛时，把意图写成可检验的候选命题：研究什么对象、在什么条件下获得什么保证、与已知结果相比要改变什么。结合已有材料比较候选的意义、可行性与代价，依[文献发现方法](../../crypto-literature-and-ideas/references/reading-and-sources.md#文献发现与依据核验)补查当前差距或工具适用性依赖的工作。区分研究价值、已有工作尚未核实与已经证实的技术差异，不把应用背景或组件组合直接写成新颖性结论。已有目标明确时直接处理当前缺口。

建立模型时，从要支持的功能或安全主张落实对象、敌手能力、算法接口和实验条件，形成可讨论的完整定义，参照下表核对关键关系。检查诚实执行能否完成任务、成功条件是否对应目标攻击，避免用限制排除原本要处理的问题。尚未确定的边界给出具体版本及对结论的影响，不把候选写成作者已确认的模型。

设计方案时，给出完成目标功能所需的全部算法，明确参数、类型、取样、输入输出、计算与必要的检查或拒绝条件。推导诚实执行的正确性，并实际检验关键安全关系，形成完整但尽量简洁的候选。按声明的模型尝试攻击，核对所依赖的绑定与未知量；可通过改变条件或增强敌手检查边界，但不将超出模型的攻击直接判为原主张失效，也不自动追加安全目标。有问题就修复对应设计并检查依赖，不只描述模块名称或承诺以后补证明。

## 先核对同一对象

从当前稿或候选定义中找出主张、算法接口、相关实验和定理，连续阅读必要依赖。检查同名对象在模型、构造、安全实验与模拟中的语义，而不只对齐符号或标题。

| 对象 | 需要核对的关系 |
| --- | --- |
| 值与密钥 | 谁取样或选择，依赖哪些输入，谁知道秘密，公私值满足什么关系，是否有版本与注册状态 |
| 敌手 | 初始知识、主动控制、替换与泄露权限、查询时序及合法输入 |
| 查询 | 输入、前置条件、状态变化、返回值、拒绝条件；替换或更新后返回原值还是当前值 |
| 成功事件或区分优势 | 如何根据敌手输出判定成功或计算优势；涉及验证时使用哪个身份、密钥、消息和状态；适用的查询、泄露限制及概率所在实验 |
| 结论 | 假设、模型、量词、优势、查询和时间范围，是否与摘要或系统性质主张一致 |

游戏用算法接口建立真实执行的取样与调用关系；构造给接口的具体实现；模拟才说明困难实例嵌入后的不同处理。不能用没有来源的赋值式补全模型，也不能仅把文字改成集合或公式就称为规范化。

共同设置可集中声明并精确继承。安全模型不必提前列出构造特有的编码和所有哈希函数；证明采用的模型及必要假设应在定义或定理可定位的位置明确。使用随机预言机时说明哪些函数被建模，以及证明实际需要的编程；不以样本省略某句为由隐藏依赖。
